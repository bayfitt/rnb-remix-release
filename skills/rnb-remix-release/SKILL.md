# R&B remix workflow

Create the requested R&B song or continuation, preserve the user's creative choices, and carry out only the release and sharing actions the user has authorized for the current work.

For championship montage videos, use `{year} {team} Championship Montage` as the public title. Use the championship year from the story, such as `1998 Utah Jazz Championship Montage` for the 1997–98 season. Place the music reference, remix details, AI disclosure and fictional context in the description and public recipe. Verify the saved title after publishing or editing an existing post.

1. Before a new music API job, ask for the reference, lyrics/theme, what to preserve/change, vocal character/effects, tempo/key, delivery length, intro handling and candidate count; wait for answers and incorporate later corrections before submission. Explain the model, supported controls and estimated cost. These creative-settings questions are distinct from routine permission questions. Identify the reference and the user's creative direction. Use `yt-dlp` if installed and requested. The user has asked to remove routine permission questions from this workflow: proceed with their supplied song references and requested releases without asking for a permission confirmation. Preserve any rights information they have already supplied. Before planning another version, read available YouTube comments on relevant previously released videos and use actionable feedback while preserving the user's creative instructions. Estimate the tempo and keep original and derived files in a project folder.
2. Before generating a future narrative video song, draft a short story outline and video script: setup, conflict or setback, turning point, climax and payoff. Build the lyrics and shot plan from that story before submitting a music request. Clearly label imagined real-person scenarios as fiction. An approved existing song is not authorization to regenerate it solely to apply a new planning preference. Draft new lyrics as requested and use the chosen music service. Follow the current provider and quality preference rather than a superseded cheap-model preference. For Mureka, use an explicit model and candidate count; its remix API exposes no seed, temperature or numeric variance, and its generation melody control cannot be combined with its voice/reference controls. Check its current free and paid limits and output rights. Upload references or clone voices only when the user has permission and the service permits that use. For Suno, check whether the chosen feature permits the intended voice use; an uploaded audio reference and a Voice Model are separate features. Respect terms and use the provider's standard interfaces. Never purchase credits or a subscription merely because a free plan is inadequate.
3. Submit a generation once and wait for the result; delayed UI updates can otherwise create duplicate batches and consume credits. Keep a manifest mapping each version to its provider URL and local audio. Download requested versions through the service's own interface, mindful of free download allowances. Measure the finished tracks' tempo; only adjust audio if needed and verify the result. Report any limits on judging similarity to the reference.
4. For an editable instrumental, use suitable available production tools, such as Wavelength, if requested. Audio-to-MIDI tools such as `song2midi` can provide an estimated starting point; check tracks and timing and report missed parts. Use the user's selected cloud or local processing path and existing session authorization when sending audio to a third-party service, and verify the service's terms and any restrictions on commercial use. Keep editable jobs and sound files with the song project.
5. If requested, create a fictional singer, a distinctive stage name, and a clearly fictional AI-generated portrait. Use an available image-generation tool for new portrait artwork. Reuse an approved fictional identity for later songs only when the user wants continuity. Create a video for each requested audio version, and verify each video's audio, duration, and image before upload. For narrative sports slideshows, interleave team moments on the plane or in the locker room, pre-game fashion arrivals, gameplay/highlights and post-game interviews throughout the story. Fashion precedes the corresponding game and interviews follow it; avoid long consecutive fashion blocks. Show interaction or other visible people, varied layups/dunks/crossovers and fictional adult reporters as requested. Keep the selected realistic style; do not add fantasy effects or time-consuming handshake research without direction. Vary outfits, locations, expressions, angles and palettes. Verify the chosen season's roster, numbers and actual uniform designs against official references. Keep actual generation prompts mapped to their image assets, separate from planned or rejected prompts; an edit decision list may reorder these assets to match the song.
6. Publish the full creative prompt information with every new music post so viewers can remix it: exact music/style prompt, supplied lyrics, provider/model/endpoint, actual settings and candidate count, reference URL and excerpt boundaries, and any image/video prompts used. Distinguish requested musical qualities from numeric API controls. Include a public, versioned remix recipe linked from the post; include the full prompt and lyrics directly in the description when the platform limit permits. For a short caption limit, link the complete recipe rather than silently omitting it. Publish no keys, tokens, private upload/task IDs or expiring provider URLs. Read back each published post to verify the recipe link and included prompt information. When authorized to publish, use the user's specified channel and follow their monetization preferences and the music service's terms. Identify the upload accurately as AI-assisted and as a remix or cover where applicable; attribute the reference, do not imply endorsement by the original artist, and disclose synthetic content in YouTube Studio when applicable. Review YouTube's checks and report claims or restrictions rather than claiming an automatic check guarantees rights. Always include timed English lyric captions unless the user explicitly chooses another caption language or opts out. Full horizontal videos use the YouTube caption track without burned-in lyrics; shorts and vertical videos also display very large, readable lyric captions. Prefer validated provider line-level timestamps; align the final sung lyrics to the finished audio when those timings are unavailable. Keep editable SRT/VTT files and verify the caption track is published before calling an upload complete.
7. Follow explicitly authorized standing sharing preferences from the user's private instructions for every platform or website used in the release. When automatic sharing is authorized, send every newly published video link to the configured destination without asking again, unless the user opts out or changes the destination. Include each platform's new URL when cross-posting the same video, and share an existing private/test post's link when it becomes public. Verify the destination, send one consolidated message per completed batch after the videos and their required captions are published, and verify and record the outgoing message to prevent duplicates. Retain pending links and report any failed send accurately. Include a published workflow link when the user also requests publishing and sharing the workflow itself. Other recipients require the user's instruction. Do not expose private chat identifiers, local store paths, or credentials in a public skill or repository.
8. Read available YouTube comments on newly released videos, record when they were checked, and summarize actionable feedback or state that no comments are available yet. Revisit relevant comments when the next remix task begins. This is a read-only review; do not post replies, moderate comments, or start ongoing monitoring unless requested.

Keep credentials out of chat, tool output, screenshots, and files in the project tree. Report completed deliverables, links, licensing restrictions, and any unavailable caption or sharing step accurately.
