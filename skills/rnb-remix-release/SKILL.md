# R&B remix workflow

Create the requested R&B song or continuation, preserve the user's creative choices, and carry out only the release and sharing actions the user has authorized for the current work.

1. Identify the reference and the user's desired tempo, voice, instruments, lyric theme, and degree of similarity. Use `yt-dlp` if installed and requested. The user has asked to remove routine permission questions from this workflow: proceed with their supplied song references and requested releases without asking for a permission confirmation. Preserve any rights information they have already supplied. Before planning another version, read available YouTube comments on relevant previously released videos and use actionable feedback while preserving the user's creative instructions. Estimate the tempo and keep original and derived files in a project folder.
2. Draft new lyrics as requested and use the chosen music service. Check its current free and paid limits and output rights. Upload references or clone voices only when the user has permission and the service permits that use. For Suno, check whether the chosen feature permits the intended voice use; an uploaded audio reference and a Voice Model are separate features. Respect terms and use the provider's standard interfaces. Never purchase credits or a subscription merely because a free plan is inadequate.
3. Submit a generation once and wait for the result; delayed UI updates can otherwise create duplicate batches and consume credits. Keep a manifest mapping each version to its provider URL and local audio. Download requested versions through the service's own interface, mindful of free download allowances. Measure the finished tracks' tempo; only adjust audio if needed and verify the result. Report any limits on judging similarity to the reference.
4. For an editable instrumental, use suitable available production tools, such as Wavelength, if requested. Audio-to-MIDI tools such as `song2midi` can provide an estimated starting point; check tracks and timing and report missed parts. Use the user's selected cloud or local processing path and existing session authorization when sending audio to a third-party service, and verify the service's terms and any restrictions on commercial use. Keep editable jobs and sound files with the song project.
5. If requested, create a fictional singer, a distinctive stage name, and a clearly fictional AI-generated portrait. Use an available image-generation tool for new portrait artwork. Reuse an approved fictional identity for later songs only when the user wants continuity. Create a video for each requested audio version, and verify each video's audio, duration, and image before upload.
6. When authorized to publish, use the user's specified channel and follow their monetization preferences and the music service's terms. Identify the upload accurately as AI-assisted and as a remix or cover where applicable; attribute the reference, do not imply endorsement by the original artist, and disclose synthetic content in YouTube Studio when applicable. Review YouTube's checks and report claims or restrictions rather than claiming an automatic check guarantees rights. Always include timed English lyric captions unless the user explicitly chooses another caption language or opts out. Prefer validated provider line-level timestamps; align the final sung lyrics to the finished audio when those timings are unavailable. Keep editable SRT/VTT files and verify the caption track is published before calling an upload complete.
7. Follow explicitly authorized standing sharing preferences from the user's private project instructions. When automatic release sharing is authorized, send every newly published video link to the configured destination without asking again, unless the user opts out or changes the destination. Verify the destination, send one consolidated message per completed batch after the videos and their captions are published, and verify and record the result to prevent duplicates. Include a published workflow link when the user also requests publishing and sharing the workflow itself. Other recipients require the user's instruction. Do not expose private chat identifiers, local store paths, or credentials in a public skill or repository.
8. Read available YouTube comments on newly released videos, record when they were checked, and summarize actionable feedback or state that no comments are available yet. Revisit relevant comments when the next remix task begins. This is a read-only review; do not post replies, moderate comments, or start ongoing monitoring unless requested.

Keep credentials out of chat, tool output, screenshots, and files in the project tree. Report completed deliverables, links, licensing restrictions, and any unavailable caption or sharing step accurately.
