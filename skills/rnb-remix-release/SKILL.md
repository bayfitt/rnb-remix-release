# R&B remix workflow

Create the requested R&B song or continuation, preserve the user's creative choices, and carry out only the release and sharing actions the user has authorized for the current work.

1. Identify the reference and the user's desired tempo, voice, instruments, lyric theme, and degree of similarity. Use `yt-dlp` if installed and requested. Confirm the user has appropriate permission for any recording, melody, or voice they ask to reuse; do not assume permission for a new reference from a prior project. Estimate the tempo and keep original and derived files in a project folder.
2. Draft new lyrics as requested and use the chosen music service. Check its current free and paid limits and output rights. Upload references or clone voices only when the user has permission and the service permits that use. For Suno, check whether the chosen feature permits the intended voice use; an uploaded audio reference and a Voice Model are separate features. Respect terms and use the provider's standard interfaces. Never purchase credits or a subscription merely because a free plan is inadequate.
3. Submit a generation once and wait for the result; delayed UI updates can otherwise create duplicate batches and consume credits. Keep a manifest mapping each version to its provider URL and local audio. Download requested versions through the service's own interface, mindful of free download allowances. Measure the finished tracks' tempo; only adjust audio if needed and verify the result. Report any limits on judging similarity to the reference.
4. For an editable instrumental, use suitable available production tools, such as Wavelength, if requested. Audio-to-MIDI tools such as `song2midi` can provide an estimated starting point; check tracks and timing and report missed parts. Check the user's permission before sending audio to a third-party service, and verify the service's terms and any restrictions on commercial use. Keep editable jobs and sound files with the song project.
5. If requested, create a fictional singer, a distinctive stage name, and a clearly fictional AI-generated portrait. Use an available image-generation tool for new portrait artwork. Reuse an approved fictional identity for later songs only when the user wants continuity. Create a video for each requested audio version, and verify each video's audio, duration, and image before upload.
6. When authorized to publish, use the user's specified channel and follow their monetization preferences and the music service's terms. Identify the upload accurately as AI-assisted and as a remix or cover where applicable; attribute the reference, do not imply endorsement by the original artist, and disclose synthetic content in YouTube Studio when applicable. Review YouTube's checks and report claims or restrictions rather than claiming an automatic check guarantees rights. If the user requests timed captions only when supplied by the generator, use provider-supplied timed captions; do not invent them.
7. Share links with the requested recipients only when explicitly instructed for the work. Verify the destination, send one consolidated message after the requested links are available, and verify the result. Do not expose private chat identifiers, local store paths, or credentials in a public skill or repository.

Keep credentials out of chat, tool output, screenshots, and files in the project tree. Report completed deliverables, links, licensing restrictions, and any unavailable caption or sharing step accurately.
